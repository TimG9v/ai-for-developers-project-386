Docker и деплой
На этом шаге мы готовим приложение к запуску в продакшене. Сделаем это с помощью Docker. Он позволяет упаковать приложение и его окружение в один образ, который одинаково запускается локально, в CI и в облаке: различий между средами меньше, и запуск проще повторить на любой платформе.

Деплой тоже отдаём агенту. У хостингов есть MCP-серверы, через которые агент создаёт сервис, выкатывает образ и проверяет, что приложение отвечает. Подключите MCP-сервер своего хостинга и попросите агента провести выкат.

По итогам шага должен получиться Docker-образ, при запуске которого приложение автоматически стартует внутри контейнера, и публичная ссылка на работающий сервис.

Требования
В репозитории должен быть файл Dockerfile. По нему в проверке собирается образ и запускается приложение.
При запуске контейнера из собранного образа приложение должно стартовать автоматически.
Приложение должно запускаться в контейнере по порту из переменной окружения PORT. Эта переменная используется и при деплое, и в автоматической проверке проекта.
После деплоя у приложения должна быть публичная ссылка, и она добавлена в репозиторий.
Ссылки
Render MCP: MCP-сервер, через который агент автоматизирует деплой и проверку сервиса в Render.
Гайд Как деплоить приложение на Render
Railway MCP: запасной вариант, если Render требует оплату или недоступен. Позволяет агенту так же автоматизировать деплой и проверку сервиса, но уже в Railway.
Задачи
Соберите Docker-образ приложения.
Подключите MCP-сервер хостинга и настройте деплой с запуском приложения по PORT. Проверьте работу приложения. Если с Render возникли проблемы (требует оплату, недоступен и так далее), задеплойте на Railway: тот же Docker-образ, запуск по PORT и публичная ссылка. Для проверки платформа не важна, важно, чтобы приложение было опубликовано и работало по PORT.
Добавьте в репозиторий ссылку на опубликованное приложение.
Результат шага
Есть Dockerfile для сборки образа, приложение запускается в контейнере по PORT и доступно по публичной ссылке.
