# step-4-ci-push-trigger-fix

- Дата: 2026-09-29 12:25
- Ветка: main
- Шаг: правка шага 4 — фикс WARNING №1 из ревью

## Причина

Ревью реализации шага 4 (WARNING №1): paths-фильтры на `push` в
`backend-ci.yml` и `frontend-ci.yml` противоречили критерию приёмки
«CI прогоняет тесты и линтеры на каждый push» (шаг 1, шаг 4: `on: push`
все ветки). Пуш, меняющий только корневые файлы (`Makefile`,
`.gitignore`, `README.md`, `AGENTS.md`), не запускал ни один workflow.

## Изменение

- `backend-ci.yml`, `frontend-ci.yml`: из `on.push` убран `paths`
  (push теперь без фильтров — все ветки, все файлы); `paths` на
  `pull_request` оставлен (экономия минут на PR из форков).
- Комментарий в обоих файлах объясняет асимметрию push/PR.

## Ruling: security.yml не менялся

WARNING №1 по существу — про тесты и линтеры. `Security` — аудиты
зависимостей: paths на манифестах в push + ежедневный `schedule`
закрывают окно обнаружения CVE без изменений манифестов. Убрать
paths из push security.yml — значит гонять компиляцию cargo-audit
(2–4 мин) на каждом пушe в main без новой информации. Ценa ошибки:
CVE в unchanged-зависимости ловится дневным cron — не «никогда».
